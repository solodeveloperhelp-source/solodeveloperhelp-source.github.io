Privacy Policy

Revision date: 2026-11-13

About the app

FastFile is a file manager for local viewing and management of files on the device. The app can perform conversion, archiving, extraction, media viewing, APK file handling, and file exchange on the local network. The main functions do not require an account, registration, or a permanent internet connection.

What data the app uses

  • Local files, folders, and Android metadata
  • Installed-app information when the user opens the apps section
  • Local FastFile settings such as language, theme, interface, security, trash, and other preferences
  • Bug report information if the user chooses to send a report to the developer
  • Firebase usage and diagnostic information when that setting is enabled
  • Local plugin identities, signing information, granted capabilities and enabled or blocked states
  • Local app integrity results and security events when local logging is enabled.

Files, their contents and metadata, the app list, settings, trash information, and activity history are processed on the device. When local logging is enabled, a separate sanitized session log is saved in private app storage for voluntary reports. Local logging is independent of automatic Firebase diagnostics; private logs are excluded from Android backup and are not sent automatically. Manual APK installations may also save a sanitized copy in shared storage.

Purposes of processing

Technical diagnostics help identify crash causes; performance analysis helps find slow startup and rendering; error information supports fixes. Remote Config is used to receive remote app configuration. Voluntary reports are used to review the described problem or suggestion and reply to the supplied email. Technical usage events help identify the section where an issue occurred.

What the app does not do

FastFile does not require an account or provide its own cloud sync. It does not automatically upload user files to a developer server. Files are transferred through a user action: Share, Open in another app, APK installation, local HTTPS access, casting to TV, or a voluntary report with attachments. This does not exclude Firebase technical data sharing when diagnostics are enabled.

Optional plugin processing also requires the user to select a file and confirm its transfer. The recipient plugin’s handling of delivered data follows its own permissions and privacy policy.

Permissions

FastFile may request file and folder access, All files access, notifications for background operations, vibration, network and Wi‑Fi information, package installation, and installed-app list access. Permissions support user-selected features and Firebase technical diagnostics.

File access uses Android mechanisms, including document and folder selection and All files access. Users can grant or revoke permissions in Android settings. Revoking access may limit related features; file permissions do not give Firebase independent access to files.

Existing Root and Shizuku functions use privileges separately granted by the user. SAF, SD cards and USB may require selecting a directory or a system device access grant. Grants can be revoked in Android or Shizuku; the corresponding operations may then be unavailable.

Optional plugins require explicit confirmation before FastFile grants capabilities and before each selected-file transfer. The confirmation shows the package name, declared developer, version, SHA-256 signing certificate hashes, requested Android permissions and FastFile capabilities. A valid APK signature does not establish the developer’s honesty or the safety of its processing. Unknown plugins are not official and have restricted FastFile capabilities. A plugin’s Android permissions are independent of its FastFile access.

Usage and diagnostics

Usage and diagnostics are off by default and enabled only when you choose. The setting on the Bug report screen controls Firebase Analytics, Crashlytics, and Performance Monitoring. Turning it off stops their collection, resets local Analytics data, and deletes unsent Crashlytics reports. It does not delete data already sent.

Crashlytics may receive the app and Android versions, device model, installation and report identifiers, app state, exception messages, and stack traces. FastFile also sets technical keys for Android API version and device model.

Performance Monitoring may collect startup duration, foreground and background time, slow and frozen frame metrics where rendering is supported, and information about the app version, OS and device. Automatic metrics depend on the SDK and device. FastFile adds technical timing measurements for opening sections, search and duplicate scans, directory reading and item counting, copying, moving, deleting, renaming, folder creation, properties retrieval, archive creation and extraction, and selected-entry extraction. Measurements may include processed item and byte counts, cache use, storage category and archive format, failures, cancellations, timeouts, retries and long operations. Network operations are measured by duration, connection latency, transferred bytes and transfer rate. Automatic HTTP/S monitoring applies to supported clients; local file access and media streams whose URLs may contain user filenames or paths are excluded from this instrumentation and do not send their URLs to Performance Monitoring. Custom measurements contain no filenames, file paths or contents, search queries, device addresses, passwords or contact details. Collection follows the existing usage and diagnostics setting.

Analytics may receive technical session events and the section_open event with the opened section name, as well as SDK-generated identifiers and usage information.

Remote Config fetches parameters when diagnostics are enabled: usage_diagnostics_enabled_default (diagnostics default), show_storage_warning (storage warning), and disable_experimental_features (disable experimental features). The SDK stores fetched values; they do not override the saved user choice. FastFile does not start a new fetch when diagnostics are off. Firebase requests may include an installation identifier, app version, language, and technical network information, including an IP address.

FastFile does not add user file contents, filenames, full local paths, or the address book to its own Firebase events and keys. However, automatic exception messages and SDK information may contain additional data if it occurs in an error or request.

Voluntary bug reports

A report contains the required description, date and time; report type; category and reply email if supplied; FastFile version and package, Android version, manufacturer, device model, board information, and report creation time. The user can include a sanitized diagnostic log and selected screenshots or files with their original data and filenames. A review appears first, then Gmail or the system app chooser opens; the user confirms sending in the selected app. The developer receives this information and email details, including the sender address. Avoid unnecessary personal data; log sanitization cannot guarantee removal of every sensitive detail from arbitrary text and attachments.

Media, PDF tools and plugins

Photos, video, audio, PDF tools, conversion, archiving, extraction, and file viewing are processed locally on the device. Transfers to other apps, devices or optional plugins require a user action.

When Cast to TV is started, the selected video or its network address is passed to the chosen Google Cast device. Local video may use a temporary HTTP stream on the local network; this is separate from local HTTPS access. Users select the receiver and stop casting themselves.

Plugins are separate Android apps. For a confirmed operation, FastFile exposes a read-only snapshot of the selected file for at most two minutes. Plugin API does not expose FastFile’s private directories or unrestricted file browsing. OCR images are re-encoded without the original EXIF metadata. A plugin may retain delivered data or transfer it using its own Android permissions and services. Review its developer’s privacy policy. Revoking access ends new Plugin API access and transfers controlled by FastFile; it cannot erase data already delivered to the plugin.

For faster previews, FastFile may extract archive files to its internal cache and keep thumbnails in memory or a local cache. Previews of hidden images and videos are created after the vault is unlocked; the hidden file list uses separate temporary decrypted copies that are deleted after processing. Thumbnails for this list are kept only in memory during the unlocked session. If the process crashes, temporary copies may remain until cache cleanup. These operations do not send files or thumbnails to the developer’s server.

Unused cached files have a shared budget of 20 MiB and are cleaned automatically. Active working copies, files handed to other apps, and data needed for recovery may temporarily use more space. They are protected while in use; unnecessary temporary files are removed after release, and recovery copies are kept until recovery can safely finish.

Launch lock and biometrics

Launch lock stores its settings locally. Biometric verification is performed by the Android system component; FastFile does not receive or store fingerprints, face data or other biometric templates.

Storage and protection

Local app data is stored on the device. Archive operations and conversion run locally with files selected by the user. Protected local HTTPS access works only after the user starts it and only within the available network. Firebase technical diagnostic data is transmitted in encrypted form. Launch lock protects access to the FastFile interface but does not replace Android screen lock, device encryption, or backups of important files.

Local settings, the private diagnostic log, and temporary files are in app storage. Uninstalling FastFile removes its private Android app data; user files and trash in shared storage are not automatically removed. Some settings may be backed up and restored by Android if system backup is enabled. App backup rules exclude diagnostic logs, protected settings, and the hidden vault.

Transferred technical information may be stored by Firebase, and voluntary reports by the developer and email providers. Retention depends on Firebase policies, service settings, and report handling; no fixed period is specified here. Uninstalling the app or disabling diagnostics does not delete data already sent. Processing or deletion questions can be sent to solo.developer.help@gmail.com; available actions depend on the service and the ability to locate the relevant data.

FastFile uses Android system mechanisms for file access; users control permissions. Protective measures reduce risks but cannot provide absolute security.

HiddenVault stores encrypted files and an encrypted index in the internal app directory. Viewing and restoring create temporary decrypted copies in the cache; interrupted operations may retain encrypted backups and recovery records. Service cache cleanup must preserve encrypted data when the index fails. The vault password is not sent to the developer. Uninstalling the app removes its internal vault; system backup of HiddenVault is disabled. Save important files outside the vault before uninstalling. The developer cannot recover a forgotten password.

FastFile verifies its installed package and signatures locally, without a developer server. Check results and local security events are not sent automatically. A confirmed modification can block regular app functions; an incomplete check may require retrying. Root access alone is not proof that FastFile was modified. Plugin identities and granted capabilities are stored locally in encrypted app storage excluded from Android backup. Local logs contain technical event labels and sanitized error traces; file contents, passwords, tokens and arbitrary action details are omitted.

Trash and deletion

When trash is enabled, deleted files may be moved to .fastfile_trash. If the user chooses permanent deletion or empties the trash, recovery through the app may be impossible.

User choices and privacy questions

Users can opt out of optional automatic diagnostics on the Bug report screen, separately choose logs and attachments for a voluntary report, manage Android permissions, and stop network access or casting. The app has no function for deleting data already sent to Firebase. Privacy, processing, or deletion requests can be sent to solo.developer.help@gmail.com.

Local logging can be disabled in Settings, independently of Firebase diagnostics. Disabling it stops local recording and log export, but does not automatically erase existing files. Plugin access can be revoked, disabled or locally blocked in the plugin screen; this does not revoke the plugin’s separate Android permissions or delete copies already received. Android settings control those permissions and uninstalling the plugin.

Children

FastFile is not specifically intended to collect personal data from children. Do not include unnecessary information about children in voluntary reports or attachments. Questions about such data can be sent to the developer at the listed email.

Policy changes

This policy may be updated when app features, permissions, Firebase diagnostics, file tools, or Google Play requirements change. The current version is shown inside FastFile and may also be published on the developer website.
